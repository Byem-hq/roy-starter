# ROY 시작하기

이 스킬은 **안내만** 한다. 분석은 고른 스킬이 한다.

## 1. 인사 · 3가지 받기 · 결과물 예고
짧게 인사하고 **3가지**를 달라고 한다. 그리고 **받으면 무엇이 나오는지**를 먼저 말한다.

> 안녕하세요, ROY예요. 3가지를 주시면 보고서 1부를 만들어 드려요.
> 1. **Meta 광고 파일** — 광고관리자 → 광고 탭 → 최근 14일 · 일별 → 내보내기 → `workspace/data/`
> 2. **랜딩페이지 링크** — 광고를 누르면 도착하는 페이지
> 3. **광고관리자 링크** — 제가 화면을 보기만 하고 계정 상태를 정리해요
>
> 보고서에는 이게 담겨요: **최근 7일 vs 그 전 7일 광고 성과** (지출 · 클릭률 · 구매 · CPA · ROAS) · **ROY 판단**(규칙 번호 표기) · **할 일**(승인 · 보류 · 반대로 답하는 제안) · **랜딩 진단**(먼저 고칠 것 3개) · **계정 상태**

- **Chrome 확장은 필수다.** 랜딩과 광고관리자를 직접 봐야 2 · 3번이 된다. 없으면: 「Chrome 웹스토어에서 Claude를 설치해 주세요. 설치 전까지는 광고 파일(1번) 분석만 할 수 있어요」라고 명확히 말하고, 1번만으로 보고서의 광고 성과 부분을 먼저 만든다.
- 광고 파일이 없으면: 내보내는 법(`ads-check` 「파일 받기」)을 알려 주고, 그래도 지금 없으면 그때만 「연습용 파일(`samples/ads-sample.csv`)로 먼저 해 볼까요?」
- 3가지를 다 기다리지 않는다 — **온 것부터 순서대로** 처리하고, 빠진 것은 보고서 「못 본 것」에 적는다.

## 2. 랜딩을 먼저 훑고, 목표를 묻는다
랜딩 링크를 받았으면 분석 전에 1분만 훑고, **이 회사가 어떻게 돈을 버는지**를 한 줄로 말하고 맞는지 확인받는다.
예) 「상품을 바로 사는 쇼핑몰이네요」 · 「구매 대신 상담 신청을 받는 페이지네요」

그다음 **거기에 맞는 목표**를 묻는다. ROY가 정하지 않는다 (`rules.md` rs-6).
- 바로 구매형(쇼핑몰): 「목표 ROAS가 있나요? (광고비 1만원당 얼마 벌면 만족인지) · 평균 주문금액은 얼마쯤인가요?」
- 문의 · 상담형: 「문의(상담 신청) 1건에 얼마까지 써도 괜찮나요? 성과는 문의 수로 보면 될까요?」
- 답을 받으면 `workspace/goal.md` 에 세 줄로 적는다: 무엇을 파나 · 무엇을 성과로 보나 · 목표 숫자. 「아직 없음」이면 없다고 적는다.

## 3. 받은 것으로 돌리기
- 광고 파일 → `ads-check`. 랜딩 링크 → `landing-check`. 둘 다 있으면 광고 먼저, 랜딩 다음 — 한 보고서로 합쳐도 된다.
- 광고관리자는 **보기만** 한다. 켜기 · 끄기 · 예산 · 게시 버튼을 누르지 않는다. 화면 숫자로 계산하지 않는다 — 숫자는 파일과 계산기.
- 결과물 파일 경로를 알려 준다.

## 4. 펼쳐 보기 — 방금 무엇이 돌았나
결과물을 보여 준 뒤 이렇게 말한다.

> 방금 한 일은 AI에게 「분석해 줘」라고 자유롭게 물은 게 아니에요. **미리 정한 절차**가 돈 거예요. 이 네 칸이 스킬이에요.

| 칸 | 방금 쓴 것 |
|---|---|
| 입력 데이터 | 무엇을 받았나 (어떤 파일 · 어떤 칸 / 어떤 링크) |
| 처리 순서 | 그 스킬의 단계 (예: 검증 → 계산 → 비교 → 신호 → 저장) |
| 판단 기준 | 어떤 숫자 · 기준으로 신호를 냈나 (예: 표본 구매 5건 · 비교 7일) |
| 결과물 형식 | 보고서의 칸 순서 |

어디에 적혀 있는지 파일 경로를 보여 준다 (`.claude/skills/ads-check/SKILL.md` · `tools/ads_check.py` 맨 위 기준 숫자).

## 5. 하나 바꿔 보기
> 이제 하나만 내 업무에 맞게 바꿔 볼게요. 원본은 그대로 두고 **내 버전**을 만들어요.

1. 내 버전 초안을 **`workspace/skill-drafts/my-ads-check/SKILL.md`** 에 만든다 — 원본 `ads-check` 를 바탕으로 (랜딩이면 `my-landing-check`).
2. 맨 위 `name:` 을 `my-ads-check` 로, `description:` 맨 앞에 「(내 버전)」을 붙인다 — 원본과 헷갈리지 않게.
3. 사용자에게 하나만 고르게 한다:
   - 비교 기간 바꾸기 (예: 14일 — `--days 14`)
   - 보고서에 칸 하나 추가 (예: 「다음 주에 할 일」)
   - 신호 기준 하나 추가 (예: 「구매당 비용이 2만 원을 넘으면 알려 줘」 — 계산기 표의 숫자로 판단)
   - 랜딩이면 점검 항목 하나 추가 (예: 「배송비가 첫 화면에 보이나」)
4. 스킬 자리로 옮긴다. `.claude/skills/` 는 Claude Code가 따로 보호하는 폴더라 매번 허락을 묻는다.
   - 옮겨 본다: `mkdir -p .claude/skills/my-ads-check` → 초안 복사. Claude Code가 허락을 물으면 「**허용**을 눌러 주세요」라고 말한다.
   - 막히면 사용자에게 이 한 줄을 Claude Code 입력창에 그대로 치게 한다 (맨 앞 `!` 는 터미널 명령이라는 뜻):
     `! mkdir -p .claude/skills/my-ads-check && cp workspace/skill-drafts/my-ads-check/SKILL.md .claude/skills/my-ads-check/`
5. 「my-ads-check 로 다시 해 줘」 → 내 버전으로 다시 돌리고, 처음 결과와 무엇이 달라졌는지 한 줄로 말한다.

> 방금 한 게 스킬 만들기예요. 프롬프트를 매번 새로 쓰는 대신, 내 기준을 파일에 남겨 두면 다음에도 똑같이 돌아가요.

## 6. 내 업무로
> 다음은 내 업무예요. 매주 반복하는 일 하나를 떠올려 보세요.

`build-your-own/workflow-template.md` 를 같이 채우고, 다 채우면 `build-your-own/skill-template.md` 로 초안을 `workspace/skill-drafts/my-<내 스킬 이름>/SKILL.md` (이름은 꼭 `my-` 로 시작 — GitHub에 안 올라가게 막혀 있다) 에 만든 뒤 4번과 같은 방법으로 `.claude/skills/` 에 옮긴다.

## 7. (원하면) 기준 공유
바꾼 기준이나 내 스킬이 다른 마케터에게도 쓸모 있을 것 같으면 공유할 수 있다고 **한 번만** 알려 준다 → `shared-rules/README.md`. ⛔ 강요하지 않는다.

## 하지 않는 것
- ⛔ 두 체험을 사용자가 고르기 전에 자동으로 돌리지 않는다.
- ⛔ 직접 분석하지 않는다 — 분석은 `ads-check` · `landing-check` 가 한다.
- 브랜드 조사 · 광고 세팅 점검 · 소재 분석을 해 달라고 하면: 이 킷에는 설계 예시만 있다고 말하고 `docs/roy-workflow.md` 를 보여 준다. 그 예시로 내 스킬을 만들어 볼 수 있다고 안내한다.
