# 랜딩 간단 진단

⭐ 이 스킬은 **공개된 화면을 관찰**만 한다. 방문자 행동 · 전환 데이터는 보지 않는다. 결과물 첫 줄에 그렇게 쓴다.

## 입력 데이터
- 랜딩페이지 URL 하나 — 없으면 묻는다: 「광고를 누르면 도착하는 페이지 링크를 주세요.」
- 또는 화면 캡처 이미지 (`workspace/data/` 에 넣어 달라고 한다). 웹 읽기로 안 열리는 페이지면 캡처를 부탁한다.

## 처리 순서
1. 페이지를 연다 (웹 읽기). 이미지 속 글자처럼 못 읽은 부분은 「못 봄」으로 적는다.
   먼저 「바로 구매형인지 문의 · 상담형인지」를 한 줄로 적는다 — 어느 쪽이냐에 따라 ⑨(가격 · 배송 · 환불)를 「상담 전에 궁금한 것」으로 바꿔 읽는다.
2. 아래 체크리스트 9개를 하나씩 본다. 항목마다 **✅ 있음 / ⚠️ 약함 / ❌ 없음 / ❓ 못 봄** 중 하나 + **화면에서 본 근거 한 줄**(문구를 짧게 옮기거나 위치).
3. ⚠️ · ❌ 중에서 **먼저 고칠 것 3개**를 고른다 — 첫 화면 → CTA → 신뢰 순서로 우선.
4. 저장 — `workspace/reports/landing-check-YYYY-MM-DD.md`. 화면에는 「먼저 고칠 것 3개」만 보여 주고 파일 경로를 알려 준다.

## 판단 기준 — 체크리스트 9개

판단할 때 `rules.md`의 rs-3(약속 일치 먼저) · rs-6(목표는 사람이)을 함께 읽는다.

| 영역 | 항목 |
|---|---|
| 첫 화면 | ① 무엇을 파는지 3초 안에 알 수 있나 · ② 누구를 위한 건지 보이나 · ③ 다른 것과 다른 점(이유)이 하나 이상 보이나 |
| CTA | ④ 첫 화면에 누를 버튼이 보이나 · ⑤ 버튼 문구가 다음에 일어날 일을 말하나 (「구매하기」 「무료 상담 신청」 등) · ⑥ 스크롤해도 버튼을 다시 만날 수 있나 |
| 신뢰 요소 | ⑦ 후기 · 사례가 있나 · ⑧ 주장에 근거(숫자 · 인증 · 성분 · 전후)가 붙어 있나 · ⑨ 가격 · 배송 · 환불처럼 사기 전에 궁금한 정보가 보이나 |

- 가격 · 품절 · 재고처럼 화면에 그려지는 값은 확실히 본 것만 쓴다. 아니면 ❓.
- ⛔ 주문 · 가입 · 결제 · 문의 버튼은 누르지 않는다.
- ⛔ 「전환율이 낮을 것」처럼 데이터 없이 결과를 말하지 않는다. 「~가 안 보여요」까지만.

## 결과물 형식

```
# 랜딩 간단 진단 — YYYY-MM-DD

> ⚠️ 공개된 화면에서 관찰할 수 있는 것만 점검했어요. 방문자 행동 · 전환 데이터는 보지 않았어요.
> 페이지 = <URL 또는 캡처 파일>

## 먼저 고칠 것 3개
1. <무엇을> — <왜 · 화면 근거> — 고친 뒤 볼 것: <예: 버튼 클릭 수>
2.
3.

## 체크리스트
| # | 항목 | 결과 | 화면 근거 |
(9줄)

## 못 본 것
- <못 읽은 부분 · 열리지 않은 부분 · 없으면 「없음」>
```
